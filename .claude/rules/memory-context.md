# Thread logs, E2B, thread cache, stored reasoning, revisions, compaction

Part of the project notes (`.claude/CLAUDE.md`); loaded when you work on these files. Keep it current in the same change as the feature.

- **Per-thread log capture** (`lib/logger` `threadLogContext` + `lib/thread-logs.ts`, `thread_logs`): an `AsyncLocalStorage` set around every non-`!secret` turn tags and captures EVERY line logged inside it (any module), flushed every 10s and at shutdown, kept 7 days.
- **E2B, lazy and persistent per thread** (per CHANNEL in a code channel): created on first touch, PAUSED not killed, reconnected next turn. Detail in `TOOLS.md`.
- **The prompt's thread read is served from memory** (`harness/thread-cache.ts`, owner's ask 2026-10-10): message events add/replace/delete in the cached copy; a real read still runs OFF the request path after every turn (kyto's streamed reply may not arrive as events) and behind every hit (`[thread-cache] … drifted` logs a mismatch); a socket reconnect clears it; app view only, never the user account's.
- **A turn that read someone's private data is replayed only on THEIR turns** (`isPrivateObservation` in `carryover.ts`, `privateTo` on a `thread_thinking` turn, `recallThinking({ speakerId })`, owner's call 2026-10-11): `thread_thinking` carries EVERY turn's reasoning AND tool calls/results (≤6000 chars each, ≤30k a turn), kept for good (owner's call 2026-10-24: no last-3 cut, no 30-day reaper); held to the SAME measured token limit as the history (no char budget, owner's call): when a turn's first request passes 90k provider-reported tokens, the excess over 60k is split between history and this block by their share of the request's chars (`thread_prompt_sizes.thinking_chars`), and the block's share is folded right after that turn by a background model call into a `summary` turn (`compactThinking`; `planThinkingCompaction` picks the oldest; per privacy owner — a private turn folds only into ITS speaker's summary; a failed summary keeps the turns unless the request passed 150k; writes serialized per thread). Classification fails CLOSED: email/memory/`mcp_*`/getFile/slackScript always private, any other non-public tool when its input/output names a `D…`/`G…` id or a privacy flag. Everyone else sees a stub saying a private turn happened.
- **Edits and deletions are remembered** (`lib/message-revisions.ts`, `message_revisions`, owner's ask 2026-10-11): the before-text of an edit and a deleted message's text, rendered in history as `[edited — earlier version: …]` / `[deleted by its author]`, so "do X", edit, "you did it wrong" can't rewrite what kyto was asked. Human, OPTED-IN authors only (stored text needs consent), threads kyto is in only; never `##`, a `<>` that didn't ping kyto, or `!secret`; token shapes redacted; 30 days; erased per author by "Your data"; the owner's clean-up shortcuts skip/clear it. A message edited INTO `##` shows only its earlier text, never into the shared digest.
- **Compaction** (`compaction.ts` + `compaction-plan.ts`): replay EVERY message; compaction is decided from a MEASUREMENT, never an estimate (owner's call 2026-10-14): each turn stores its first request's provider-reported input tokens and its size in chars (`thread_prompt_sizes`); when that reached 90k, the next turn folds just enough of the oldest messages (at that request's measured tokens/char) to come back to ~60k, never re-expanding behind the last measured window. The digest also gets what kyto DID per message (`thread_thinking.actions`, one line per tool call, kept 200 turns; a private turn's masked). An unmeasured thread's first request is capped at 300k chars only so it can't overflow the context window. No message cap, fold older into `<earlier_in_this_thread>`, which always states the count. The read is INCREMENTAL from the digest's marker; a walk that doesn't reach the end RE-ANCHORS near now and skips compaction; the boundary is found by TIMESTAMP; a backlog is chunked into persisted passes of 200, >1 pass in the background.
- **Mid-turn compaction** (`@repo/ai/context-trim.ts`, owner's asks 2026-10-12): Haiku 5.5 bills the WHOLE request ~5x past 100k input tokens, luna 2x in / 1.5x out past 272k (`LONG_CONTEXT_PRICE_STEP`; luna added 2026-10-18 — never compacted below its step, which would only rewrite a cached prompt). When a step's ACTUAL input (provider usage, never an estimate) passes 92% of that step (92k haiku, ~250k luna), `prepareStep` asks the SAME model for a summary of everything but the system prompt and tools — same system/tools/messages + `COMPACT_INSTRUCTION`, tools without `execute`, `toolChoice` untouched (changing it drops Anthropic's message cache), so the summary request is a cache READ — then sends summary + the task's request + the last step verbatim. Failure → old tool results cut to their heads. Billed as `<source>-compaction`. Every `streamAttempt` caller compacts; the main turn and subagents show a "Compacting context" card with the measured saving; Kevinton only logs.
- **Memory = the Slack thread.** No transcript persisted; derived text is: `thread_thinking` (kept for good), `thread_summaries` (~30 days), `memories`. Owner signed off; see `docs/reference/security.md`.
