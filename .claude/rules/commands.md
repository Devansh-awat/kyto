# `!commands`, CLI flags, thread clean-up, bans, moderation

Part of the project notes (`.claude/CLAUDE.md`); loaded when you work on these files. Keep it current in the same change as the feature.

- **Commands** (`lib/commands.ts`): a body starting `!word` is answered by the harness, no model turn, never touching an in-flight turn except `stop`. `!focusmode`, `!secret`, `!ban`, `!optout`, `!timings` (anyone: the thread's last 5 turns' stage timings from `turn_timings`, kept 30 days, `lib/turn-timings.ts`), `!spend [days]` (OWNER only: since UTC midnight, by whose key paid, then source and model/effort, from `model_spend`; as a thread REPLY, that thread's bill), `!effort [days] [source]` (OWNER only: haiku vs luna per effort, `model_spend.stats`), `!debug` (OWNER only: freezes the thread's timings, 24h of captured logs, stored reasoning, digest and kept edits — secrets redacted — into `debug_snapshots`, viewed at `/_dashboard/debug/<random id>`, kept 90 days), CLI flags at the start of a message, or ending a line outside code (known flags with a valid value only, owner's call 2026-10-13) `--model luna|haiku|mercury|glm|<slug>` `--reasoning none…high` `--focusmode [@x…|off]` `--no-memory` `--NO-MEMORY` `--memory`, `--show-reasoning [off]` (the user-account persona posts each finished thought as a `task_card` block from its own token before the text it led to — the bot token only if that post is refused; nothing on a silent skip), owner-only `--no-redact` (one message only, never saved) (`lib/flags.ts`; anyone, sticky per thread; the model never sees them — `withoutFlags` strips them from the message, history, steering and Jev, and a flags-only message is dropped from history; a non-kyto slug needs the picker's own key and runs on THEIR turns only). The memory flags differ by CASE (owner's ask 2026-10-11, stored in `thread_model_choices.memory_mode`): lowercase keeps everything but tells kyto memories/notebooks/earlier reasoning may be stale and not to rely on them; CAPS hides them all — no `<memories>` list (not even read), no notebooks, no `thread_thinking` replay, no `memory` tool (subagents and reminders in the thread too); `--memory` restores. Unknown `!word` falls through.
- **Thread clean-up** (`features/thread-cleanup`, OWNER-ONLY message shortcuts, re-checked on modal submit): "Delete kyto's replies" (a confirm modal with the count, then stops any turn in the thread and deletes every message from the app or kyto's account, each by its own identity) and "Delete message" (kyto's own, or the owner's via `SLACK_USER_TOKEN`; Slack lets only admins delete other people's). Both clear the thread's `thread_thinking` and `thread_summaries` — Slack history is kyto's memory, so that resets its context.
- **Bans** (`/kyto ban @x 1d reason`, owner-only via `runBanCommand`; **the model has no ban tool**). Gates being ANSWERED, not read. One ephemeral to the banned person; ban/unban announced in `OPT_IN_CHANNEL`. Durations parsed strictly (`1dave` refused), capped at a year, reason required. **`/kyto` keeps `should_escape: true`.**
- **Moderation** (`lib/moderation.ts`): after every non-owner turn, its message, the author's custom instructions (once per text), the reply and its tool results (sexual categories only — a page about a war is "violence") go in ONE call to Hack Club's moderation proxy (free, not logged, 5000/30 min). Bare `violence`, `harassment` and `illicit` never count; `violence/graphic`, `harassment/threatening` and `illicit/violent` do. A flag in a PUBLIC channel ADDS the owner (even one he left), then pings him in the thread; a PRIVATE one never adds him — his DM gets its name, id and a link (owner's call 2026-10-17); `!secret`: DM, no content. It never blocks or bans — the owner bans by hand (owner's call 2026-10-02). A repeat flag from the same author in the same thread within 30 min pings again only for a NEW category (issue #53).
