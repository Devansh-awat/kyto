# Models, fallback, caching, BYOK, resumed turns, spend

Part of the project notes (`.claude/CLAUDE.md`); loaded when you work on these files. Keep it current in the same change as the feature.

- **Primary: `anthropic/claude-haiku-5.5` on Hack Club AI, pinned to Anthropic's own API** (`ANTHROPIC_ONLY_MODELS`, owner's call 2026-10-10): **Jev picks the reasoning effort** (`medium`/`high`: `low` left every automatic pick 2026-11-21, owner's call, after 19 of 20 skips ran at low; `--reasoning low`, BYOK settings and the cap-filled retry keep it; owner's call 2026-10-17, in the preload call): haiku takes its pick every turn; on luna EVERY effort has its own cache, so the SAME pick only raises the thread's stored effort (`thread_luna_efforts`; a lower pick is ignored; owner's call 2026-10-18) — but only while that cache can be warm: a stored effort older than 10 min is ignored. No Jev answer → haiku draws at random, luna keeps its stored effort (else medium). `--reasoning` wins; other models stay medium; a `high` attempt gets 16k output tokens. Logged as `reasoningBy` + `jevEffort` (with Jev's probabilities) in `turn_timings`; `!effort` compares. **Haiku vs luna is an experiment** (owner's calls 2026-10-11/20; mercury dropped 2026-11-08 when Hack Club stopped serving it, MODELS.md): a thread with no `--model` leads with one of the two, by a hash of the thread id (`experimentAttempt`) — per THREAD, each model has its own cache; logged as `experimentModel`. **Mercury 3** (gone since 2026-11-08): diffusion, text-only (images sent as descriptions), 429s retried 2×. Luna is otherwise the first fallback rung, then GLM 5.3 Flash. TokenBom stays removed unless the owner asks.
- **OpenAI models fill EVERY tool field, optional or not**: on an `openai/`/`gpt-` request every optional property is rewritten to also accept `null` (`nullable-optionals.ts`), which luna then sends, and a null optional is dropped before the tool's zod sees it. Other models' bytes are untouched (cache).
- **Hack Club requests exclude fp4 upstream hosts** (`provider.quantizations` in `tuneBody`) — fp4 GLM turns into word salad on long contexts. GLM 5.3 Flash additionally sorts by throughput under a `max_price` cap (MODELS.md).
- **A haiku "empty response" is usually Anthropic's safety filter**: a `content-filter` stop, its reason only in the stream's `delta.refusal` text (`captureRefusal` in `agent.ts` → `holder.refusal`), named in the error, the logs and the footer (e.g. `reasoning_extraction`: "…duplicating model outputs"). From 2026-11-21 it hit ~45% of haiku turns in two channels and almost none elsewhere. Its parts pass alone (system prompt, channel notebook, replayed reasoning: 0 refusals in 72 tries), so the refused request body is written to `/tmp/kyto-refusals/` on the pod (newest 20, gone on restart, never `!secret`) to bisect.
- **Hack Club 504s are its proxy's 5s header timeout**; gateway statuses are replayed ≤2× inside the fetch (`gateway-retry.ts`), and a 504 does not condemn the tier (`condemnsHackclub`).
- An attempt is **handled** iff it produced text or a `skip`; tools-but-no-text gets ONE `synthesizeFinalAnswer` nudge — and a reply cut mid-work whose nudge writes nothing is a `StreamInterruptedError` (next model continues), not "handled" on its earlier narration. A streamed turn may still fall back for exactly three reasons: degenerate loop, watchdog, `StreamInterruptedError`. A stream cut with no finish reason is a transport drop — continued or re-run in place.
- **Hard failures are remembered 30 min across turns** (`fallback-cache.ts`; 401/402/403/404/spend limit/a 429 saying the quota is spent; shared attempts only; no background probe; cleared if it would leave nothing to try).
- **`upgradeModel`** escalates to kimi-k3 → claude-sonnet-5, once per turn, 8/day, and sticks to the thread for 30 min on the same budget.
- **Every non-turn call draws haiku or luna per run** (`drawnAttempts`, owner's call 2026-10-17; MODELS.md), effort too; Gemini is only the floor. A finished subagent keeps its WHOLE conversation (reasoning, tool calls, results) for an hour and anyone in its thread may `resume` it (owner's call 2026-10-16); a resume over 100k tokens is compacted on its first request like a late step. Each run is told who asked and when, stops at 200 tool calls, reports ≤30k chars (TOOLS.md).
- **A fallback attempt gets EXACTLY what the failed attempt last sent** (owner's call 2026-10-27): `streamAttempt` reports every request's messages as sent (`onSentContext`, `SentContext` in `packages/ai/src/sent-context.ts`), and the next attempt is handed the last one (`resumeFrom`) — its compaction summary, the steps after it, everything — with only its OWN prompt swapped in as the request (it names the model writing), reasoning parts and provider metadata dropped (signed per provider), call ids prefixed `carried-` (Gemini's signature check), and calls to tools it lacks dropped with their results. Its first request is measured by that request's predecessor (`inputTokens`; none right after a compaction), so step-0 compaction applies. Rebuilding from `gatheredResults` instead resurrected everything the failed model had compacted away — luna's 190k became one 901k haiku request ($0.87). **Except onto Gemini** (#158): the owner's Gemini key is free tier, 250k input tokens a minute per model, so a failed request estimated over 200k tokens (`sentTokens`: its measured head + chars/3 for the rest) is NOT handed to a Gemini rung; it gets the bounded rebuild below instead. Handed 900k-1.8M chars, all three Gemini rungs 429'd within seconds on 2026-10-27. A RESTART (no request in memory) also rebuilds, via `carriedMessages` (ids `carried-N`), bounded to the most recent results within `CARRIED_TOTAL_MAX` chars. The recovery nudges still use the text `renderCarryover`.
- **Prompt caching** (detail in MODELS.md): gpt-6-luna looks a cache up ONLY at message endings/breakpoints, and an uncached token is a cache WRITE at 1.25x (12.5x a read). So: system = static half (breakpoint, shared by every thread) + per-thread context half (`subagentSystemPrompt` too — its fixed `note` goes in the static half, never per-run text); `buildPrompt` returns `history` (ONE user message per Slack message, breakpoint on the last) + `tail` (thinking, clock, new message); never render a history entry differently between turns. Tools are the front of the prefix: the `loadTools` catalog lists every deferred tool (stable), and the tool order persists PER THREAD (`threadToolOrder`). Luna's cache lives ~10 min (measured). `turn complete` logs `costUsd`. Gemini needs `thought_signature` replay.
- **Flex** (`serviceTier: 'flex'`, half price, OpenAI on Hack Club only): BACKGROUND work only — Kevinton and subagents (owner's call 2026-10-08); live turns stay default until flex latency is measured. A refused flex request is re-sent once at the normal tier. Flex has its own cache, separate from the default tier.
- **Stall watchdog** `ATTEMPT_TIMEOUT_MS` (5m idle, re-armed on activity; aborts the attempt only). A truncated tool call is repaired — `writeFile`/`postMessage` only; a command tool never runs a cut-off prefix.
- **BYOK / Sign in with ChatGPT**: gated on `BYOK_ENCRYPTION_KEY` (AES-256-GCM); `packages/db` returns plaintext only via `listUserModelCredentialSecrets`/`getChatgptAccountSecret`; a key is never logged, prompted, put in a sandbox or `private_metadata`. **Model mode** per user: own first / kyto's only / kyto's with a switch to own on a coding flag. A spent ChatGPT quota is PARKED until reset. A key's owner sets its **max output tokens** (App Home, 1k–128k, blank = 32k, 64k at `high`; `max_output_tokens`) and its **reasoning effort** (low/medium/high, blank = Jev's pick per turn, never past `high`; sent in each API's own format only to keys that take it — OpenRouter-style `reasoning.effort`, flat `reasoning_effort` for custom/mebbo and for reasoning-model slugs on OpenAI/xAI/Groq/Gemini (`byokEffortFormat`), never Anthropic; a 400/422 naming the field is retried without it and remembered; the card names an effort only when one is sent; `reasoning_effort`; a `--reasoning` flag wins) (#95). An attempt whose thinking fills the cap with no text and no tool call is re-run ONCE on the same model at `low` effort before falling back (#73).
- **A turn a restart cut short is resumed** (`lib/agent/inflight.ts`, `inflight_turns`): SIGTERM marks rows `interrupted` BEFORE `stopAllTurns`; the new instance CLAIMS them atomically within 30 min of their last HEARTBEAT, never `!secret`: after EVERY clean shutdown and EVERY crash (>2 min stale heartbeat), no cap (owner's call 2026-10-31; a crash used to get one resume, so a turn an OOM killed twice ended on "won't pick this up on its own"). A turn that crashes kyto deterministically would loop, so a crash's cause gets fixed, not capped. **Outward actions are a ledger** (`inflight_turns.effects`, `startEffect` around `EFFECT_TOOLS` in `toolset.ts`'s `trackUse`): written `started` BEFORE the call, `done`/`failed` after, kept across resumes; a back-to-back identical repeat of the last done one is REFUSED (`repeatedEffect`, #123; not images/speech); the resumed turn's prompt lists each as DONE (don't redo) or STARTED-UNKNOWN (check first). Uploads, images, embeds, mermaid and speech are in the ledger too (#99). **A restart must have no visible impact** (owner's ask 2026-10-19): every minute and at the shutdown cut the turn CHECKPOINTS its tool calls with full results (≤60k chars each) + reply text so far (`checkpointTurn`, `inflight_turns.checkpoint`); the resumed turn carries them in as REAL messages exactly like a fallback (`isFallback`), posts no "restarted" note, and a cut stream's stop closes its open cards. Reasoning still goes to `thread_thinking`. A `wait` is in the ledger too (#77): a wait the restart cut is resumed for the time LEFT (or skipped if it's over), not restarted.
- **Every paid model call is a `model_spend` row, kept for good** (owner's ask 2026-10-11): `streamAttempt` reports each call's steps through `setSpendSink` (`packages/ai/src/spend.ts`, `source` per caller), on finish AND abort; Jev, vision, summarize-thread and image generation report their own. Thread id AND **`user_id`** come from the log context (`threadLogContext`). Read with `!spend`.
- **Per-user daily cap on the SHARED Hack Club budget** (`DAILY_SHARED_CAP_USD`, $1 list price, owner's call 2026-10-27): for a user who is NOT the owner and has NO own key (`routing.own.length === 0`), never a `!secret` turn. Checked at turn start AND before EVERY Hack Club request the turn causes (owner's ask 2026-11-22: "fix the 1$ cap to actually cap it"): `executeTurn` sets `sharedCap: 'enforced'` on the turn's log context, and `streamAttempt` opens a `SpendGate` (`packages/ai/src/spend.ts`, `openGate` in `apps/bot/src/lib/spend.ts`) whose `beforeRequest` runs inside the fetch, so steps, compaction summaries, recovery calls, subagents (background ones too) and the thread digest all pass it; `generateImage` calls `assertSharedCap` itself. Spend = booked rows (`sumUserSharedSpendSince`, UTC day) + `unbooked` (finished steps of calls still running, rows being written): a row is written only when a whole call ends, and one call ran 14 requests and 15 compactions, $2 past the cap. At the cap: `SharedCapError`, no fallback (not to Gemini either, like a refusal at the start), no rung marked dead, text streamed so far stays, the person gets the ephemeral "connect a key" notice. The overshoot is bounded by the requests already in flight when it is reached. Jev's calls count but aren't gated; reminders run outside a turn's context, so they are neither counted nor gated. Fails OPEN on a DB read error (booked counts as 0).
