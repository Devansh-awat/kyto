# The coding agent (Crush, tool `opencode`) and anti-coding

Part of the project notes (`.claude/CLAUDE.md`); loaded when you work on these files. Keep it current in the same change as the feature.

- **The coding agent** (`tools/opencode.ts`, still named `opencode`; `packages/sandbox/src/coding-agent.ts`): code work is delegated to it silently, NOT in `CODE_TOOLS`. Since 2026-10-19 it is **Crush** (pinned Go binary, ~80 MB vs OpenCode's 465-620 MB, which OOM'd the 1 GB sandbox), `crush run -q [-C]`, on the owner's OmniRoute via the **host-side model proxy** (`lib/code-model-proxy`, `/_codemodel/v1/chat/completions`): per-run token in the sandbox, real `CODE_MODEL_API_KEY` added on the host, model forced to `CODE_MODEL` (default `deepseek-flash`), 400 calls/run; unset env → the tool says code work is unavailable. **It must never reach Slack** (its model's provider may train): the turn's Slack proxy token is SUSPENDED host-side for the run (`suspendSlack` — the real boundary; the PATH wrapper's `unset` alone was readable via `/proc/$PPID/environ`), its rules say so, the brief must carry nothing from Slack. A media-only brief is sent back to bash ONCE per turn (`isMediaOnlyBrief`, #110). **One run per sandbox** (in-sandbox `flock`; parallel refused); `minutes` caps a run (≤18), a timed-out one returns its `changedFiles` (#124); the proxy logs `[code-model] call` per model call (latency, status). **An exhausted route fails fast** (#154): a 402/quota/"cooling down" answer (also sniffed from a 200 stream's head) marks the route down 10 min (a bare 429: 1 min); meanwhile the proxy answers 400 (Crush doesn't retry it) and the tool refuses to start a run or a `continue`. **An aborted run is KILLED** (`onAbortCommand`, its process group), a lock held >20 min by WALL clock is taken over. Its watchdog extension is a HOLD a sibling tool's result can't shorten.
- **Anti-coding** (`lib/anti-coding/`): coding-agent work never runs on Hack Club AI's shared key — **it goes to OpenCode** (`opencode` tool, its own free models, default `opencode/deepseek-v4.1-flash-free`, owner's call 2026-10-15). **Jev judges the WORK** (threshold 0.9, fails OPEN, every score logged): at turn START on the thread as of kyto's last answer plus the new message (`jevContexts`, in memory, never `!secret`; owner's call 2026-10-10) and before every `CODE_TOOLS` call on the full thread — except a provably read-only or PUBLISHING shell command (a DOCUMENT — README, notes, a skill file — and committing/PRing it is not coding, owner's call 2026-10-15; `not-coding.ts`, tested: `echo`/`ls`/`git status`/`gh issue list`/a GET `gh api`, `git clone`/`fetch` of an https repo and `gh repo clone` (reading a repo isn't building; none of the flags that run a program; owner's call 2026-10-13), and `git init`/`add`/`commit`/`push`, `gh pr create`/issue/comment, `gh repo create`/`fork` (#108), a `&&` or `;` chain counts if EVERY command in it does, `2>&1 | tail -N` peeled off, quoted text is only text; nothing else unquoted that could chain, redirect or expand), which skips it. **A catch is SILENT** (owner's call 2026-09-30): the turn gets a `<coding_work>` note, a caught tool call returns WHY (the score, and the publishing/read-only shape that skips the check, so kyto retries a chained `git push && gh pr create` instead of inventing an approval) and then "use opencode", and the person gets the result as kyto's own work — never a refusal, never "I'm not a coding agent". kyto doesn't volunteer OpenCode but may say if asked ("not VERY important"); told NOT to use it, kyto doesn't call it and says code work on kyto's models goes through it, or their own key (App Home → Models) skips it (#64). **OpenCode exists only on kyto's shared key, per ATTEMPT** (owner's call 2026-10-14): while a person's own key runs, `opencode` is filtered out of `activeTools` and the attempt's prompt carries the own-key coding line (`codingLine` in `prompt.ts`; the rule is not in the static prompt); a fallback to the shared chain gets the OpenCode rule and the tool back — a caught call there says their key IS linked but failed, use opencode, never "link a key". Own-key attempts code directly (a flag keeps that turn off the shared chain). Making or editing a FILE stays in bash, even with a short script: ImageMagick, ffmpeg (owner's call 2026-10-17), a 3D model/STL (owner's call 2026-10-26), a PDF — in `codingLine`, the `opencode` description and both Jev questions. `deploySite` is for everyone and not in `CODE_TOOLS` (hosting runs no model). The plan card reads "Working on the code". Questions are framed on what kyto DELIVERS — code as a TOOL is fine.
