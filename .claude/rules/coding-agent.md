# The coding agent (pi, tool `codingAgent`) and anti-coding

Part of the project notes (`.claude/CLAUDE.md`); loaded when you work on these files. Keep it current in the same change as the feature.

- **The coding agent** (`tools/coding-agent.ts`, tool `codingAgent` — `opencode` until 2026-10-31, renamed at the owner's ask since OpenCode was long gone; `packages/sandbox/src/coding-agent.ts`): code work is delegated to it silently, NOT in `CODE_TOOLS`. Since 2026-10-31 it is **pi** (`@earendil-works/pi-coding-agent`, pinned npm package under `/home/user/.kyto/pi`, `--ignore-scripts`, reinstalled when the `.version` marker differs; `pi -p [-c] -- <brief>` with extensions/skills/MCP/templates/themes off and `-na`; rules appended from `~/.pi/agent/kyto-rules.md`; `models.json` defines one model `kyto/kyto-code` whose key is `$KYTO_CODE_MODEL_TOKEN`, read from env at run time, never written to a file). It replaced **Crush** (2026-10-19 to 2026-10-31) because of TOKENS: Crush put 9.6k tokens of prompt + 18 tool schemas in front of every call and the route allowed ~20k tokens/min; pi's 4 tools + prompt are ~1.4k, ~160 MB peak. OpenCode (before Crush) OOM'd the 1 GB sandbox at 465-620 MB. It runs on the owner's OmniRoute via the **host-side model proxy** (`lib/code-model-proxy`, `/_codemodel/v1/chat/completions`): per-run token in the sandbox, real `CODE_MODEL_API_KEY` added on the host, model forced to `CODE_MODEL` — **one model or a comma list; runs ALTERNATE between them, per run not per call** (a mid-run switch loses the prompt cache; half glm-5.3 / half claude-sonnet-5, owner's call 2026-10-31: `CODE_MODEL=kav/glm-5.3,kav/claude-sonnet-5`, OmniRoute's `kav` provider = `ai.kavyansh.org`, $6/day and $30/month; the `opencode-only` key's `allowedModels` must list every model named here, or the proxy gets 403 "not allowed for this API key"), skipping a model that is down; 400 calls/run. **Every call and run is priced at LIST prices** (`LIST_PRICES`, OpenRouter, per million tokens; the provider shows kyto no spend, owner's ask 2026-10-31): `[code-model] call` carries tokens/cached/`costUsd`, `[code-model] run` the run's totals. **The proxy adds a missing `finish_reason`** before `[DONE]` (one router's Claude stream sends none, and the agent retried such a stream 4 times). **The proxy turns off Bun's 10 s idle timeout for its requests** (`server.timeout(request, 0)`: a reasoning model streams nothing while thinking, Bun cut the stream and the agent failed `stream transport error: INTERNAL_ERROR`, 2026-10-31). unset env → the tool says code work is unavailable. **It must never reach Slack** (its model's provider may train): the turn's Slack proxy token is SUSPENDED host-side for the run (`suspendSlack` — the real boundary; the PATH wrapper's `unset` alone was readable via `/proc/$PPID/environ`), its rules say so, the brief must carry nothing from Slack. A media-only brief is sent back to bash ONCE per turn (`isMediaOnlyBrief`, #110). **One run per sandbox** (in-sandbox `flock`; parallel refused); `minutes` caps a run (≤18), a timed-out one returns its `changedFiles` (#124); the proxy logs `[code-model] call` per model call (latency, status). **An exhausted route fails fast** (#154): a 402/quota/"cooling down" answer (also sniffed from a 200 stream's head) marks the route down 10 min (a bare 429: 1 min); PER MODEL: meanwhile that model's calls get a 400 (the agent doesn't retry it), a new run takes another model, and the tool refuses to start a run or a `continue` only when every model is down. **An aborted run is KILLED** (`onAbortCommand`, its process group), a lock held >20 min by WALL clock is taken over. Its watchdog extension is a HOLD a sibling tool's result can't shorten.
- **Anti-coding** (`lib/anti-coding/`): coding-agent work never runs on Hack Club AI's shared key — **it goes to the coding agent** (pi on the owner's OmniRoute, `CODE_MODEL`; nothing the model reads calls it OpenCode, owner's call 2026-10-31). **Jev judges the WORK** (threshold 0.9, fails OPEN, every score logged): at turn START on the thread as of kyto's last answer plus the new message (`jevContexts`, in memory, never `!secret`; owner's call 2026-10-10) and before every `CODE_TOOLS` call on the full thread — except a provably read-only or PUBLISHING shell command (a DOCUMENT — README, notes, a skill file — and committing/PRing it is not coding, owner's call 2026-10-15; `not-coding.ts`, tested: `echo`/`ls`/`git status`/`gh issue list`/a GET `gh api`, system diagnostics (`id`, `ps`, `free`, `grep`, `sha256sum`, `systemctl status`-style verbs, `command -v`, a `find` with no `-exec`/`-delete`) and a GET `curl`/`wget` download (#26: an install's preflight was refused at 0.94, allowed at 0.81 six hours later), with any chain of filters after it (`| grep|sort|uniq|head|tail|wc|jq|cut|tr`, `sed`/`awk` that write and run nothing), `||` like `&&`, redirects to `/dev/null`, globs and `$VAR` as plain words, `timeout`/`time`/`sudo -n` wrappers, `--version`, package listings, archive listings, and read-only git in every form (`remote -v`, `branch --show-current`, `diff --check`, `ls-files`, `config --get`…: refused at 0.94-0.98 on 2026-11-01, #26; READ-ONLY WORK IS NEVER GATED, owner's call 2026-11-06, and both Jev questions say so too), `git clone`/`fetch` of an https repo and `gh repo clone` (reading a repo isn't building; none of the flags that run a program; owner's call 2026-10-13), and `git init`/`add`/`commit`/`push`, `gh pr create`/issue/comment, `gh repo create`/`fork` (#108), a `&&` or `;` chain counts if EVERY command in it does, `2>&1 | tail -N` peeled off, quoted text is only text; nothing else unquoted that could chain, redirect or expand), which skips it. **A catch is SILENT** (owner's call 2026-09-30): the turn gets a `<coding_work>` note, a caught tool call returns WHY (the score, and the publishing/read-only shape that skips the check, so kyto retries a chained `git push && gh pr create` instead of inventing an approval) and then to use `codingAgent`, and the person gets the result as kyto's own work — never a refusal, never "I'm not a coding agent". kyto doesn't volunteer the coding agent but may say if asked ("not VERY important"); told NOT to use it, kyto doesn't call it and says code work on kyto's models goes through it, or their own key (App Home → Models) skips it (#64). **The coding agent exists only on kyto's shared key, per ATTEMPT** (owner's call 2026-10-14): while a person's own key runs, `codingAgent` is filtered out of `activeTools` and the attempt's prompt carries the own-key coding line (`codingLine` in `prompt.ts`; the rule is not in the static prompt); a fallback to the shared chain gets the coding-agent rule and the tool back — a caught call there says their key IS linked but failed, use `codingAgent`, never "link a key". Own-key attempts code directly (a flag keeps that turn off the shared chain). Making or editing a FILE stays in bash, even with a short script: ImageMagick, ffmpeg (owner's call 2026-10-17), a 3D model/STL (owner's call 2026-10-26), a PDF — in `codingLine`, the `codingAgent` description and both Jev questions. `deploySite` is for everyone and not in `CODE_TOOLS` (hosting runs no model). The plan card reads "Working on the code". Questions are framed on what kyto DELIVERS — code as a TOOL is fine.
